# Лабораторная работа №3. Параллельное умножение квадратных матриц (MPI)

## 1. Описание алгоритма

### 1.1 Параллельное перемножение матриц
В данной лабораторной работе последовательный алгоритм умножения матриц (C = A × B) был модифицирован для распараллеливания вычислений на нескольких узлах/ядрах с использованием стандарта **MPI (Message Passing Interface)**.

**Особенности реализации:**
- **Распределение данных:** 
  - Процесс 0 (master) считывает исходные матрицы A и B из файлов.
  - Матрица B (множитель) рассылается целиком всем процессам с помощью `MPI_Bcast`, так как каждый процесс использует её столбцы для вычислений.
  - Матрица A (множимое) разбивается на горизонтальные блоки (наборы строк) и распределяется между всеми процессами с помощью функции `MPI_Scatterv`.
- **Локальные вычисления:** Каждый процесс умножает свой локальный блок матрицы A на матрицу B, используя оптимизированный порядок обхода циклов **i-k-j** (что улучшает использование кэша процессора).
- **Сборка результатов:** Вычисленные локальные блоки результирующей матрицы C собираются обратно на нулевом процессе с помощью `MPI_Gatherv`.

### 1.2 Вычислительная сложность
- Количество операций: **2N³** суммарно (разделено на $P$ процессов).
- Передача данных: рассылка $N^2$ элементов B, распределение и сборка матриц A и C.

## 5. Анализ результатов

### 5.1 Масштабируемость и Ускорение
Внедрение MPI продемонстрировало высокую эффективность распараллеливания на больших объемах данных. Для матриц размера $N=2000$ алгоритм показал:
- На 2 процессах: ускорение **1.85x**.
- На 4 процессах: ускорение **3.06x**.
- На 8 процессах: ускорение **3.62x**.

Алгоритм не демонстрирует идеального (линейного) ускорения $S=P$, что связано с накладными расходами MPI:
1. Затраты времени на пересылку матриц (`MPI_Bcast` и `MPI_Scatterv`/`Gatherv`).
2. Ограничения пропускной способности памяти (memory bound), так как все потоки/ядра одновременно пытаются читать матрицу B и обращаться к ОЗУ при вытеснении из кэша.

### 5.2 Зависимость от размера матрицы
- При малых матрицах ($N=200..400$) использование 8 ядер дает скачок с 0.021 сек до 0.006 сек. Накладные расходы на MPI коммуникации здесь сопоставимы с временем вычислений, поэтому эффективность ниже.
- При увеличении размера данных вычислительная часть растет как $O(N^3)$, а коммуникационная — $O(N^2)$. Поэтому на больших $N$ ускорение стабильно высоко. Тем не менее, для 8 ядер ускорение составляет 3.6x, что типично для алгоритмов с интенсивной работой с памятью на процессорах с разделяемым кэшем и единой шиной памяти (архитектура обычного ПК).

## 6. Выводы

1. **Реализовано параллельное умножение матриц** с применением технологии обмена сообщениями MPI. Успешно применено распределение данных с помощью `Scatterv/Gatherv`.
2. **Экспериментально подтверждена эффективность алгоритма.** В сравнении с последовательной версией, использование 4-8 процессов позволило сократить время умножения 2000x2000 матриц с ~4.8 секунд до ~1.3 секунд.
3. Продемонстрирован эффект "ограничения пропускной способности памяти" (memory wall). Так как все MPI-процессы работают на одном физическом узле (Core i7), рост количества процессов выше 4-6 ядер не дает линейного прироста из-за исчерпания пропускной способности шины ОЗУ.
