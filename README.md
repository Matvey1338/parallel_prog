# Лабораторная работа №2. Многопоточное умножение квадратных матриц (OpenMP)

## 1. Описание алгоритма

### 1.1 Порядок обхода i-k-j

Стандартный алгоритм умножения матриц C = A × B:

```
C[i][j] = Σ(k=0..N-1) A[i][k] * B[k][j]
```

В реализации используется порядок циклов **i-k-j**:

```cpp
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    for (int k = 0; k < n; k++) {
        double a_ik = A[i * n + k]; // загружаем один раз
        for (int j = 0; j < n; j++) {
            C[i * n + j] += a_ik * B[k * n + j];
        }
    }
}
```

**Особенности i-k-j:**
- Внутренний цикл по `j` обращается к `B[k][j]` и `C[i][j]` последовательно по строке (stride=1), что оптимально для кэша.
- Значение `A[i][k]` вынесено во временную переменную — исключается повторное обращение к памяти.

**Распараллеливание (OpenMP):**
- Использована директива `#pragma omp parallel for` перед внешним циклом `i`.
- Вычисление разных строк результирующей матрицы `C` распределяется между потоками.
- Так как каждый поток записывает данные строго в свою уникальную строку матрицы `C`, конфликтов доступа (data races) не возникает, и необходимость в синхронизации отпадает, что дает максимальную производительность.

### 1.2 Хранение матриц

Матрицы хранятся в одномерных массивах (`new double[n*n]`) с линейной индексацией `[i*n+j]`.

### 1.3 Вычислительная сложность

- Количество операций: **2N³** (N³ умножений + N³ сложений)
- Сложность по памяти: **3N²** элементов типа `double` (24N² байт)

## 5. Анализ результатов

### 5.1 Масштабируемость и Ускорение (Speedup)
- **Накладные расходы:** На малых размерах матриц (например, N=200) ускорение может быть далеко от идеального, так как время, затрачиваемое на создание и синхронизацию потоков в OpenMP, становится сопоставимо с самим временем полезных вычислений.
- **Насыщение (Memory Wall):** С увеличением количества потоков до 8 (и более), рост производительности часто перестает быть линейным из-за того, что узким местом становится пропускная способность оперативной памяти (ПСП), а не вычислительные мощности ядер.

### 5.2 Влияние кэша в многопоточной среде
При параллельном выполнении каждый поток активно загружает свои фрагменты матриц A, B и C в кэш своего ядра (L1/L2). При больших размерах N матрицы перестают помещаться даже в общий L3 кэш, что вызывает лавину кэш-промахов (cache misses) и задержек при обращении к ОЗУ. Из-за этого графики производительности (GFLOP/s) для всех конфигураций потоков обычно показывают пик на малых-средних матрицах (N=400..800) и постепенный спад при N=1600+.

## 6. Выводы

1. **Реализовано распараллеливание** алгоритма умножения квадратных матриц с помощью технологии OpenMP. Оптимальный обход циклов `i-k-j` идеально подошел для параллельной обработки по строкам без необходимости синхронизации (отсутствие data races).
2. **Экспериментально подтверждена** эффективность многопоточности: время выполнения значительно сокращается по мере добавления новых потоков.
3. **Анализ узких мест:** Наблюдается ограничение масштабируемости (sub-linear speedup) на большом числе ядер, что обусловлено накладными расходами на управление потоками (на малых N) и ограничениями пропускной способности оперативной памяти (на больших N).
