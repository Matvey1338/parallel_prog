# Лабораторная работа №4. Умножение квадратных матриц с использованием CUDA

## 1. Описание алгоритма

В данной лабораторной работе реализовано параллельное умножение матриц (C = A × B) на графическом ускорителе (GPU) с использованием платформы **NVIDIA CUDA**. 

### 1.1 Архитектура CUDA-ядра
Вычисления переносятся с центрального процессора (CPU) на тысячи потоков видеокарты (GPU).
**Особенности реализации:**
- **Иерархия потоков:** Вычислительная сетка (Grid) разбита на двумерные блоки (Block). Размер блока задается параметрами `block_size` × `block_size` (в экспериментах исследовались размеры 8×8, 16×16 и 32×32).
- **Маппинг потоков:** Каждый поток в CUDA-ядре отвечает за вычисление ровно одного элемента результирующей матрицы `C[i][j]`.
- **Локальные вычисления:** Поток циклически проходит по строке матрицы `A` и столбцу матрицы `B`, перемножая соответствующие элементы и накапливая сумму.
- **Память:** Исходные матрицы копируются из оперативной памяти хоста (RAM) в глобальную память устройства (VRAM) с помощью `cudaMemcpy`. После завершения вычислений результат аналогичным образом возвращается на хост.

### 1.2 Вычислительная сложность
- Количество операций: **2N³** суммарно. Однако они распределены между $N^2$ независимыми потоками, поэтому каждый поток выполняет $2N$ операций.
- Сложность по памяти: $3N^2$ элементов типа `double`. Обмен данными между CPU и GPU является узким местом (bottleneck) и занимает существенную часть времени при малых $N$.

## 5. Анализ результатов

### 5.1 Вычислительная мощность GPU
Перенос вычислений на видеокарту позволил достичь колоссального прироста производительности.
Максимальная достигнутая скорость составила **248.73 GFLOP/s** (при N=2000, block_size=16). 
Для сравнения, однопоточная версия на CPU выдавала ~4-6 GFLOP/s, а многопоточная MPI версия ~12 GFLOP/s. Ускорение GPU по сравнению с одним ядром CPU достигает **~40-60 раз**.

### 5.2 Влияние размера матрицы
- При малых матрицах (N=200) производительность составляет всего ~33 GFLOP/s. Это объясняется недостаточной загрузкой GPU: блоков слишком мало, чтобы полностью занять все потоковые мультипроцессоры (SM) видеокарты.
- Начиная с N=800 производительность стабилизируется на уровне >200 GFLOP/s. GPU полностью утилизирован.

### 5.3 Влияние размера блока (Block Size)
Были протестированы размеры блоков: 8x8 (64 потока), 16x16 (256 потоков), 32x32 (1024 потока).
- Блок **8x8** показывает слегка сниженную производительность (на ~5%), так как размер блока (64) лишь немногим больше размера warp-а (32 потока), что может приводить к неоптимальному планированию потоков внутри SM.
- Блоки **16x16** (256 потоков) стабильно показывают **наилучшие результаты** на всех размерах матриц. Это идеальный баланс между использованием регистров на поток и количеством активных warp-ов (occupancy).
- Блоки **32x32** (1024 потока) также показывают высокую производительность, но местами чуть уступают 16x16 из-за исчерпания аппаратных лимитов на количество регистров для одного блока (register spilling).

## 6. Выводы

1. **Реализовано умножение матриц на CUDA.** Архитектура GPU с тысячами ядер идеально подходит для задач с независимыми параллельными вычислениями, таких как матричное умножение.
2. **Экспериментально подтверждена** подавляющая вычислительная мощь GPU (до 248 GFLOP/s для типа данных `double`), что на порядки превосходит возможности CPU.
3. Оптимальным размером блока для данной задачи является **16x16**.
4. Основным ограничением для CUDA на малых объемах данных является низкая загрузка устройства (latency bound), а на больших объемах — скорость глобальной памяти GPU (memory bandwidth bound). Дальнейшая оптимизация алгоритма потребует использования разделяемой памяти (Shared Memory / Tiled Matrix Multiplication) для минимизации обращений к глобальной VRAM.
